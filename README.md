# AI แชท ออนไลน์ / ออฟไลน์

เว็บแอปแชทกับ AI ที่ใช้งานได้แม้ไม่มีอินเทอร์เน็ต เป็น **static site ล้วน ๆ**
(HTML/CSS/JS) ไม่มีเซิร์ฟเวอร์ของตัวเอง ดีพลอยขึ้น GitHub Pages ได้ฟรี — ข้อมูล
ทั้งหมดเก็บอยู่ในเครื่อง (browser `localStorage`) ก่อนเสมอ และถ้าตั้งค่า
**Google Sheets sync** ไว้ด้วย ข้อมูลจะซิงก์ขึ้น/ลงอัตโนมัติเมื่อมีเน็ต ทำให้
เปิดจากเครื่องไหนก็เห็นแชทและข้อมูลออฟไลน์ตรงกัน (ไม่มีเน็ตก็ยังใช้แอปได้ปกติ
แค่ไม่ซิงก์จนกว่าจะมีเน็ตอีกครั้ง)

แอปยังติดตั้งเป็น **PWA แบบ offline-first** ได้ด้วย (ผ่าน Service Worker) —
เปิดใช้งานตอนมีเน็ตสักครั้งหนึ่งแล้ว ครั้งต่อ ๆ ไปเปิดแอปได้แม้ไม่มีเน็ตเลย
ไม่ใช่แค่ตัว AI ที่ตอบแบบออฟไลน์ได้ แต่ตัวหน้าเว็บเองก็โหลดได้แบบออฟไลน์ด้วย

> หมายเหตุ: โปรเจ็กต์นี้เป็นแอปส่วนตัว/สาธิต ระบบ login เป็นแค่ด่านกั้นง่าย ๆ
> (ชื่อผู้ใช้/รหัสผ่านตายตัวฝังในโค้ด) **ไม่ใช่ระบบความปลอดภัยจริง** เพราะเป็น
> static site ไม่มี backend ตรวจสอบ ใครก็ดูซอร์สโค้ดเห็นได้ ถ้าต้องการความ
> ปลอดภัยจริงต้องมีเซิร์ฟเวอร์ตรวจสิทธิ์แยกต่างหาก

## ✨ ฟีเจอร์

- **หน้า Login** — ชื่อผู้ใช้ `meen` รหัสผ่าน `5340` (แก้ไขได้ในไฟล์ `js/common.js`)
- **หน้า AI แชท**
  - แดชบอร์ดแชทแบบฟองข้อความ (bubble) พร้อมเวลาไทย (Asia/Bangkok)
  - ไฟสถานะ 🟢 ออนไลน์ / 🔴 ออฟไลน์ ตามการเชื่อมต่ออินเทอร์เน็ตจริง (`navigator.onLine`)
  - ปุ่มสลับโหมด AI **ออนไลน์ / ออฟไลน์** — ถ้าไม่มีเน็ตจะสลับเป็นออฟไลน์ให้อัตโนมัติ
  - โหมดออนไลน์: เรียก **Groq API** (มีโควตาใช้งานฟรี ไม่ต้องผูกบัตร) โมเดลเริ่มต้น
    ตอนนี้คือ `openai/gpt-oss-120b` — ถ้าเครื่องไหนเคยตั้งค่าเป็นโมเดลรุ่นเก่าที่ Groq
    เลิกให้บริการไปแล้ว (เช่น `llama-3.3-70b-versatile`) แอปจะสลับให้เป็นโมเดลปัจจุบันเอง
    อัตโนมัติ ไม่ต้องเข้าไปกดบันทึกซ้ำทีละเครื่อง
  - โหมดออฟไลน์: ตอบจากคู่ "คำ/คำตอบ" ที่คุณกำหนดไว้เอง เก็บในเครื่อง — จับคู่แบบ
    สองทาง (ข้อความที่พิมพ์มีคีย์เวิร์ดแฝงอยู่ หรือคีย์เวิร์ดมีข้อความที่พิมพ์แฝงอยู่)
    และถ้ามีคีย์เวิร์ดที่ match มากกว่า 1 รายการ จะรวมทุกคำตอบเข้าเป็นคำตอบเดียว
    (ขึ้นต้นแต่ละส่วนด้วยชื่อคีย์เวิร์ด) ให้ฟีลเหมือน AI ตอบครบในทีเดียว
  - ข้อมูลออฟไลน์ถูกตรวจสอบก่อนเสมอ แม้อยู่ในโหมดออนไลน์ (ตอบไว ไม่ต้องยิง API ถ้ามีคำตอบสำเร็จรูปอยู่แล้ว)
- **หน้าข้อมูล (Data)** — เพิ่ม/แก้ไข/ลบคู่ "คีย์เวิร์ด → คำตอบ" สำหรับโหมดออฟไลน์
  มีปุ่มย้อนกลับไปหน้าแชท
- **PWA / Service Worker** — cache ไฟล์ทั้งหมดของแอปไว้ในเครื่อง เปิดใช้งานได้แม้
  ไม่มีเน็ตเลย ไม่ว่าจะเปิดจาก Safari ตรง ๆ หรือจากไอคอนที่เพิ่มไว้หน้าจอโฮม
  (ต้องเปิดตอนมีเน็ตอย่างน้อย 1 ครั้งก่อน ให้ Service Worker ติดตั้งและ cache สำเร็จ)
  อัปเดตแคชให้เองอัตโนมัติทุกครั้งที่เปิดตอนมีเน็ต ไม่ต้องยุ่งอะไรเพิ่ม
- ไอคอนแอป `1.png` ใช้เป็น favicon และไอคอนเวลา "เพิ่มไปหน้าจอโฮม" บนมือถือ
- ธีมสีดำ (dark theme) ทั้งแอป
- รองรับ Safari บน iPhone 6s / iOS 15.8.8 (ใช้ฟอนต์ระบบ, CSS ที่เข้ากันได้กับ
  เบราว์เซอร์รุ่นเก่า, ปุ่ม/ฟอนต์ขนาดที่ไม่ทำให้ Safari ซูมอัตโนมัติ, layout แถบบนสุด
  ปรับให้พอดีจอแคบ 375px ไม่มี horizontal scroll)

## 📁 ไฟล์ในโปรเจ็กต์

```
ai-chat-app/
├── index.html          หน้า Login
├── ai.html              หน้า AI แชทหลัก (แดชบอร์ด + toggle online/offline)
├── data.html             หน้าจัดการข้อมูลออฟไลน์ (คีย์เวิร์ด → คำตอบ)
├── manifest.json        web app manifest (ไอคอนตอนเพิ่มหน้าจอโฮม)
├── sw.js                 Service Worker (cache ไฟล์แอปไว้ใช้งานออฟไลน์)
├── 1.png                 ไอคอนแอป
├── css/
│   └── style.css         สไตล์ทั้งหมด (ธีมดำ, responsive)
├── js/
│   ├── common.js          ค่าคงที่ + ฟังก์ชันร่วม (auth guard, เวลาไทย, storage helper, ซิงก์ Google Sheets, ลงทะเบียน Service Worker)
│   ├── auth.js            ตรรกะหน้า login
│   ├── chat.js            ตรรกะหน้าแชท (โหมด, Groq API, จับคู่ข้อมูลออฟไลน์, ซิงก์แชท)
│   └── data.js            ตรรกะหน้าจัดการข้อมูลออฟไลน์ (ซิงก์คู่คีย์เวิร์ด-คำตอบ)
└── README.md            ไฟล์นี้
```

อัปโหลดไฟล์/โฟลเดอร์ทั้งหมดข้างต้นขึ้น GitHub ตามโครงสร้างเดิม (อย่าลืมโฟลเดอร์
`css/`, `js/` และไฟล์ `sw.js` ที่ต้องอยู่ระดับเดียวกับ `index.html` เท่านั้น — ห้ามย้าย
เข้าไปในโฟลเดอร์ย่อย ไม่งั้น scope ของ Service Worker จะครอบคลุมไม่ถึงทุกหน้า)

`Code.gs` (อยู่นอกโฟลเดอร์นี้) **ไม่ต้องอัปขึ้น GitHub** — เอาไปวางใน Google Apps
Script แทน (ดูขั้นตอนด้านล่าง)

## 🚀 วิธีดีพลอยขึ้น GitHub Pages (ฟรี)

1. สร้าง repository ใหม่บน GitHub เช่นชื่อ `ai-chat-app`
2. อัปโหลดไฟล์ทั้งหมดในโฟลเดอร์นี้ขึ้น repo (ลาก-วางผ่านหน้าเว็บ GitHub ได้เลย
   หรือใช้ `git push` ถ้าถนัด command line)
3. ไปที่ repo → **Settings** → เมนูซ้าย **Pages**
4. หัวข้อ **Build and deployment** → Source เลือก **Deploy from a branch**
5. เลือก Branch เป็น `main` (หรือ `master`) และโฟลเดอร์เป็น `/ (root)` แล้วกด **Save**
6. รอประมาณ 1–2 นาที จะได้ลิงก์ประมาณ
   `https://<ชื่อผู้ใช้>.github.io/ai-chat-app/`
7. เปิดลิงก์นั้นบนมือถือ/คอม ก็ใช้งานได้ทันที — จะเพิ่มเป็นไอคอนหน้าจอโฮมก็ได้
   (Safari → ปุ่มแชร์ → "เพิ่มไปยังหน้าจอโฮม")
8. เปิดแอปตอนมีเน็ตอย่างน้อย 1 ครั้งก่อน เพื่อให้ Service Worker ติดตั้งและ cache
   ไฟล์ทั้งหมดสำเร็จ — หลังจากนั้นจะเปิดใช้งานได้แม้ไม่มีเน็ตเลย

> GitHub Pages ให้บริการผ่าน HTTPS ฟรี ซึ่งจำเป็นสำหรับให้เบราว์เซอร์อนุญาตใช้
> โหมดออฟไลน์/แคชข้อมูลได้อย่างถูกต้อง (Service Worker ทำงานได้เฉพาะบน HTTPS
> หรือ localhost เท่านั้น)

## 🔑 การตั้งค่า AI ออนไลน์ (Groq API — ฟรี)

โหมดออนไลน์เรียกใช้ Groq API โดยตรงจากเบราว์เซอร์ (ไม่มี backend เป็นตัวกลาง)
จึงต้องมี **API Key ส่วนตัว** ใส่ในแอปครั้งเดียว แล้วจะถูกเก็บไว้ในเครื่องนั้น ๆ
(localStorage) ไม่ถูกส่งไปที่ไหนอื่นนอกจาก Groq — เลือกใช้ Groq แทน Gemini เพราะ
ช่วงนี้ Gemini มีปัญหาคีย์รูปแบบใหม่ (`AQ.`) ใช้งานกับ REST API ตรงๆ ไม่ได้กับ
หลายบัญชี (บั๊กฝั่ง Google ที่ยังไม่ได้แก้) ส่วน Groq ให้บริการฟรีโดยไม่ต้องผูกบัตร
และเสถียรกว่าในตอนนี้

**ขั้นตอนขอ API Key ฟรี:**

1. เปิด [console.groq.com](https://console.groq.com/) แล้วสมัคร/เข้าสู่ระบบ (อีเมล
   หรือ Google/GitHub ก็ได้ ไม่ต้องผูกบัตรเครดิต)
2. ไปที่เมนู **API Keys** → **Create API Key**
3. คัดลอกคีย์ที่ได้ (ขึ้นต้นด้วย `gsk_...`)
4. เปิดแอปของคุณ → หน้า AI แชท → กดไอคอนรูปเฟือง ⚙︎ (ตั้งค่า) มุมขวาบน
5. วางคีย์ลงในช่อง **Groq API Key** แล้วกด **บันทึก**
6. ช่อง **ชื่อโมเดล** ค่าเริ่มต้นคือ `openai/gpt-oss-120b` (Groq เลิกให้บริการ
   `llama-3.3-70b-versatile` แล้วตั้งแต่ 16 ส.ค. 2026) ถ้าต้องการโมเดลอื่นดูรายชื่อ
   ได้ที่หน้า Models ใน Groq Console — ถ้า Groq เลิกใช้โมเดลตัวไหนอีกในอนาคต แค่
   เติมชื่อโมเดลนั้นเข้า `DEPRECATED_GROQ_MODELS` ใน `js/common.js` แอปจะสลับให้ทุก
   เครื่องอัตโนมัติโดยไม่ต้องไล่กดตั้งค่าทีละเครื่อง

> คีย์นี้ผูกกับบัญชี Groq ของคุณ **อย่าแชร์คีย์ให้คนอื่น** และอย่า commit คีย์
> ลงใน GitHub เพราะไฟล์ในโปรเจ็กต์นี้ไม่ได้เก็บคีย์ไว้ในโค้ด — คีย์อยู่ใน
> localStorage ของเบราว์เซอร์ที่คุณกรอกเท่านั้น แต่ละเครื่อง/เบราว์เซอร์ต้องกรอก
> คีย์แยกกัน 1 ครั้ง (ยังไม่มีวิธีซิงก์คีย์ข้ามเครื่องอัตโนมัติ เพราะเสี่ยงคีย์รั่ว
> ถ้าจะทำต้องผ่าน Apps Script เพิ่มและยอมรับความเสี่ยงตรงนั้น)

## 📴 โหมดออฟไลน์ทำงานอย่างไร

- แอปตรวจสอบสถานะเน็ตจริงด้วย `navigator.onLine` — ถ้าไม่มีเน็ต ไฟสถานะจะเป็น
  สีแดงและสลับเป็นโหมดออฟไลน์ให้อัตโนมัติ
- ในหน้า **ข้อมูล** ให้เพิ่มคู่ "คีย์เวิร์ด → คำตอบ" เช่น
  - คีย์เวิร์ด: `Hi, สวัสดี`
  - คำตอบ: `Yo`
- การจับคู่คำ ทำงาน 3 ขั้น:
  1. **ตรงกันเป๊ะ** — ถ้าข้อความที่พิมพ์ตรงกับคีย์เวิร์ดพอดี ใช้คำตอบของคีย์เวิร์ดนั้น
  2. **จับคู่แบบสองทาง** — ข้อความที่พิมพ์มีคีย์เวิร์ดแฝงอยู่ (เช่น พิมพ์ประโยคยาวที่มี
     คำว่า "Hi" อยู่) **หรือ** คีย์เวิร์ดมีข้อความที่พิมพ์แฝงอยู่ (เช่น พิมพ์แค่ "key"
     สั้น ๆ ก็ match กับคีย์เวิร์ดยาวอย่าง "Api Key" ได้ — กันคำสั้นกว่า 2 ตัวอักษร
     ไม่ให้ไป match แบบนี้ เพื่อไม่ให้จับคู่มั่ว)
  3. ถ้า match ได้มากกว่า 1 คีย์เวิร์ด จะ**รวมทุกคำตอบเข้าเป็นคำตอบเดียว** ขึ้นต้น
     แต่ละส่วนด้วยชื่อคีย์เวิร์ดของมัน คั่นด้วยบรรทัดว่าง
- ถ้าพิมพ์คำที่ไม่มีในฐานข้อมูลออฟไลน์เลย แอปจะแจ้งว่ายังไม่มีข้อมูล พร้อมชวนไปเพิ่ม
  ในหน้าข้อมูล
- ข้อมูลชุดนี้ถูกใช้ตรวจสอบก่อนเสมอแม้อยู่ในโหมดออนไลน์ (ถ้าเจอคำตอบสำเร็จรูป
  จะตอบทันทีโดยไม่ยิง Groq API) — พอกลับมาต่อ Wi-Fi ก็ใช้โหมดออนไลน์ต่อได้
  โดยไม่ต้องตั้งค่าอะไรใหม่ เพราะทุกอย่างเก็บอยู่ในเครื่องเดิม

## 📲 ใช้งานแบบออฟไลน์เต็มรูปแบบ (PWA / Service Worker)

นอกจาก AI ที่ตอบแบบออฟไลน์ได้แล้ว ตัวหน้าเว็บเองก็โหลดได้แบบออฟไลน์ด้วย ผ่าน
`sw.js` ที่ cache ไฟล์ทั้งหมดของแอป (`index.html`, `ai.html`, `data.html`,
`manifest.json`, `1.png`, `css/style.css`, `js/*.js`) ไว้ในเครื่อง

**วิธีใช้:**
1. เปิดแอปตอนมีเน็ตอย่างน้อย 1 ครั้ง (ให้ Service Worker ติดตั้ง + cache สำเร็จ)
2. หลังจากนั้นปิดเน็ตแล้วเปิดแอปใหม่ได้เลย ไม่ว่าจะเปิดจาก Safari ตรง ๆ หรือจาก
   ไอคอนที่เพิ่มไว้หน้าจอโฮม

**กลยุทธ์การ cache:** stale-while-revalidate — ตอบจากแคชทันที (เร็ว + ใช้ได้
ออฟไลน์) แล้วแอบไปเช็ค/อัปเดตแคชจากเน็ตเบื้องหลังให้เองทุกครั้งที่เปิดตอนมีเน็ต
เพราะงั้น **แก้โค้ดแล้ว push ปกติได้เลย ไม่ต้องทำอะไรเพิ่ม** ผู้ใช้จะได้เวอร์ชันใหม่
เองอัตโนมัติในครั้งถัดไปที่เปิดตอนมีเน็ต

ข้อยกเว้นที่ต้องแก้เพิ่ม: ถ้า **เพิ่ม/ลบไฟล์** ออกจากโปรเจกต์ (เช่นเพิ่มหน้าใหม่)
ต้องไปแก้เลข `CACHE_NAME` ใน `sw.js` (เช่น `"aichat-shell-v1"` → `"aichat-shell-v2"`)
เพื่อบังคับล้างแคชเก่าทันที ไม่งั้นแคชเก่าจะยังค้างอยู่เรื่อย ๆ

แชท/ข้อมูลออฟไลน์ที่เก็บใน `localStorage` เป็นคนละส่วนกับแคชของ Service Worker
โดยสิ้นเชิง — อัปไฟล์ใหม่ทับ หรือ Service Worker อัปเดตแคช จะไม่ทำให้แชท/ข้อมูล
หายเลย ตราบใดที่ไม่เปลี่ยนชื่อ key ใน `LS_KEYS` (`js/common.js`)

## 🧪 ทดสอบก่อนอัปโหลด (ไม่บังคับ)

เปิดไฟล์ `index.html` ตรง ๆ ในเบราว์เซอร์ก็ทดสอบได้เลย (ไม่ต้องมีเซิร์ฟเวอร์)
หรือถ้าต้องการรันผ่าน local server (แนะนำสำหรับทดสอบ manifest/PWA/Service Worker):

```bash
# ในโฟลเดอร์โปรเจ็กต์
python3 -m http.server 8000
# แล้วเปิด http://localhost:8000
```

> Service Worker ทำงานได้เฉพาะบน HTTPS หรือ `localhost` เท่านั้น — เปิดไฟล์
> `index.html` ตรง ๆ แบบ `file://` จะทดสอบส่วนออฟไลน์-แคชไม่ได้ ต้องรันผ่าน
> local server หรือ GitHub Pages จริงเท่านั้น

## 🔄 ซิงก์ข้อมูลข้ามเครื่องด้วย Google Sheets (ทางเลือกเสริม)

ถ้าไม่ตั้งค่าส่วนนี้ แอปจะยังใช้งานได้ปกติทุกอย่าง แค่ข้อมูลจะอยู่แยกเครื่องใครเครื่องมัน
ถ้าอยากให้ทุกเครื่อง/เบราว์เซอร์เห็นแชทและข้อมูลออฟไลน์ตรงกัน ให้ทำตามนี้:

### ขั้นตอนที่ 1: สร้าง Google Sheets + Apps Script

1. ไปที่ [sheets.google.com](https://sheets.google.com) สร้างสเปรดชีตใหม่ ตั้งชื่ออะไรก็ได้
2. เมนู **ส่วนขยาย (Extensions) → Apps Script**
3. ลบโค้ดเดิมทั้งหมด แล้ววางโค้ดจากไฟล์ `Code.gs` (อยู่นอกโฟลเดอร์เว็บ ไม่ได้อัป GitHub)
4. เช็คว่า `SYNC_TOKEN` ในไฟล์นี้ตรงกับ `SYNC_TOKEN` ใน `js/common.js` (ค่าเริ่มต้นคือ `"meen"` ทั้งคู่ ถ้าจะเปลี่ยนต้องแก้ให้ตรงกันทั้งสองที่)
5. กด **Deploy → New deployment** → Select type: **Web app**
   - Execute as: **Me**
   - Who has access: **Anyone**
6. กด Deploy แล้วอนุญาตสิทธิ์ตามที่ระบบขอ
7. คัดลอก **Web app URL** ที่ได้ (ลงท้ายด้วย `/exec`)

ไม่ต้องสร้างชีตหรือหัวตารางเอง — โค้ดจะสร้างชีต `ChatHistory` และ `OfflineData`
พร้อมหัวตารางให้อัตโนมัติตอนเรียกใช้ครั้งแรก

> 🔁 **ทุกครั้งที่แก้โค้ดใน Apps Script** ต้องกด **Deploy → Manage deployments →
> แก้ไข (ไอคอนดินสอ) → Version: New version → Deploy** ใหม่เสมอ ไม่งั้นระบบจะยัง
> ใช้โค้ดเวอร์ชันเก่าอยู่

### ขั้นตอนที่ 2: ใส่ URL ไว้ล่วงหน้าในโค้ด (ไม่ต้องกรอกทุกเครื่อง)

เปิด `js/common.js` แก้บรรทัด:

```js
const DEFAULT_SCRIPT_URL = "วาง Web app URL จากขั้นตอนที่ 1 ตรงนี้";
```

หรือถ้าไม่อยากแก้โค้ด จะไปกรอกในแอปเองก็ได้ที่ **หน้าแชท → ไอคอนเฟือง ⚙︎ →
ช่อง "Apps Script URL"** แล้วกดบันทึก (ค่านี้เก็บใน localStorage ของเครื่องนั้น)

### ใช้งานจริง

- พิมพ์แชท/เพิ่มข้อมูลออฟไลน์ตามปกติ — ถ้ามีเน็ตและตั้งค่า URL ไว้แล้ว ระบบจะส่ง
  ขึ้น Google Sheets ให้อัตโนมัติเบื้องหลัง (ไม่ต้องกดปุ่มอะไรเพิ่ม)
- เปิดแอปจากอีกเครื่องที่ตั้งค่า URL เดียวกัน แล้วต่อเน็ต ระบบจะดึงแชท/ข้อมูลที่
  ขาดไปมาเติมให้อัตโนมัติตอนเปิดหน้า
- ถ้าพิมพ์แชทตอนไม่มีเน็ต ข้อความจะถูกเก็บไว้ในเครื่องก่อน แล้วส่งขึ้นซิงก์ให้เอง
  ทันทีที่เน็ตกลับมา (ไม่ต้องพิมพ์ซ้ำ)
- คีย์ Groq API และชื่อโมเดลที่ตั้งไว้ **ไม่ได้ซิงก์** ผ่านช่องทางนี้ (ตั้งใจ เพื่อ
  ความปลอดภัย) — ต้องกรอกแยกทีละเครื่องผ่านหน้าตั้งค่าเสมอ

## ⚙️ ปรับแต่งเพิ่มเติม

- เปลี่ยนชื่อผู้ใช้/รหัสผ่าน: แก้ค่า `FIXED_USERNAME` / `FIXED_PASSWORD` ใน
  `js/common.js`
- เปลี่ยนสีธีม: แก้ค่าตัวแปร CSS ในส่วน `:root` ของ `css/style.css`
  (เช่น `--accent`, `--bg-base`)
- เปลี่ยนโมเดล Groq เริ่มต้น: แก้ `DEFAULT_GROQ_MODEL` ใน `js/common.js`
- เพิ่มรายชื่อโมเดลที่ Groq เลิกให้บริการ (เพื่อให้ทุกเครื่องสลับโมเดลอัตโนมัติ):
  เติมชื่อเข้า array `DEPRECATED_GROQ_MODELS` ใน `js/common.js`
- บังคับล้างแคช Service Worker ทันที (เช่นหลังเพิ่ม/ลบไฟล์ในโปรเจกต์): แก้เลข
  `CACHE_NAME` ใน `sw.js`
- ล้างข้อมูลทั้งหมด (แชท/ข้อมูลออฟไลน์/คีย์): เปิด Developer Tools ของเบราว์เซอร์ →
  Application/Storage → Clear site data สำหรับเว็บนี้
